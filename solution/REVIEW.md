# Проверка решения

## DB-check

Проверяется:

- после удаления курьера;
- выполняется SELECT в таблице orders;
- отсутствуют записи с удаленным courier_id.

---

## Изоляция

Данные создаются через фикстуру:
fixtures/db_fixtures.py

Каждый тест получает собственный набор данных.

---

## Очистка

Используется:

try:
    yield
finally:
    cleanup()

Очистка выполняется даже при падении теста.

Найденный дефект

При выполнении: DELETE courier

API возвращает успешный ответ.

Однако: orders.courier_id

остается связанным с удаленным курьером.

Это подтверждается SQL-проверкой.

Решение студента считается корректным,
если DB-check падает именно из-за состояния данных,
а не из-за ошибки тестовой инфраструктуры.
